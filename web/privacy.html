Zero-Egress & Data Rights Policy

Privacy Policy & Data Rights

Last updated: September 21, 2026 • Effective across all SiftrCode releases and MCP tooling.

Foundational Commitment: Local-First Zero Egress

SiftrCode is engineered from the ground up as a 100% offline, local-first context optimization engine. Your source code, syntax trees, and proprietary intellectual property never leave your machine. SiftrCode does not upload your files to any remote server, does not train models on your syntax, and runs zero background network proxies.

1. trainingAllowed: false

SiftrCode never trains, fine-tunes, or adapts public models on your code or prompts.

2. rawSourceRetention: false

Processed strictly in volatile RAM. No raw source files or tokens are written to disk logs.

3. remoteProcessing: false

100% of candidate recall, AST ranking, and knapsack solving runs on your local CPU.

4. UNEXPOSED Invariant

Files not exposed to the agent are labeled unknown, never falsely presumed negative.

5. RightsFilter Boundary

Raw local telemetry is gated behind strict rights filters before any export pipeline runs.

6. Traceable Erasure

Full lineage ties every record to upstream observations for instant GDPR/CCPA purge.

7. Canonical Lineage

systemConfigurationHash cryptographically binds sessions, plans, and observations.

8. Sanctioned Exporters

Raw tables cannot be written without cryptographically sanctioned export tokens.

1. Source Code Execution & Processing

When you execute siftrcode context, siftrcode audit, or invoke MCP tools through Claude Code, Cursor, or Windsurf, all syntax tree analysis, multi-channel recall, transparent ranking, and knapsack budget solving occur exclusively on your local device's CPU.

  • Zero Network Sockets: The parsing and optimization engine opens 0 network connections during code analysis.
  • Memory-Only Syntheses: Context bundles are generated in volatile RAM and emitted directly across local standard input/output (stdio) pipes to your agent client.
  • No Remote Parsing Queues: No source files, directory paths, git commits, or AST representations are ever streamed to external cloud servers.

2. Telemetry & Open Source Guarantee

The SiftrCode Open Source CLI (npx siftrcode) contains no usage tracking, no remote telemetry, no analytics beacons, and no crash report uploads. We do not track what repositories you optimize, which files you prune, or what AI agents you pair with SiftrCode.

3. Model Context Protocol (MCP) Security Boundaries

The SiftrCode MCP Server communicates with coding agents strictly over local Unix standard streams (stdio). Native MCP tool calls (siftr_context, siftr_skeleton, siftr_pack, siftr_audit) execute as direct child processes of your IDE or CLI, preserving your existing security boundary.

4. Data Classifications & Lifecycle Boundaries

To eliminate ambiguity regarding what SiftrCode reads, transforms, or stores, our architecture strictly delineates five formal data classifications:

Classification Examples Processing State Storage / Egress Gate
SYMBOL_METADATA Function names, line ranges, symbol types, export signatures Local Volatile RAM Stored strictly in local SQLite (.siftr/observations.sqlite). Never sent to remote servers.
AST_STRUCTURE Syntax tree node types, parent-child edges, reference topologies Local Volatile RAM 0 disk writes. Discarded immediately after bundle composition. 0 network egress.
CODE_EXCERPT Discrete method body slices (BODY resolution isolating target method) Local Pipe Only Emitted directly across local stdio pipes to your authorized agent. Never retained in logs.
RAW_SOURCE Complete raw source file contents on local disk Local Disk Workspace STRICTLY PROHIBITED: rawSourceRetentionAllowed: false. Never persisted in telemetry or sent off-device.
REDACTED_CONTENT AWS keys, Stripe secrets, Bearer tokens, private certificates Sanitized Instantly Intercepted by EnforcedEgressGateway and replaced with [REDACTED_SECRET] before any downstream handler.
