THE 6-STAGE OUTCOME PIPELINE

The 6-Stage Optimization Engine

SiftrCode V2 replaces naive single-file token stripping with a formal multi-stage context pipeline designed to maximize first-turn task completion rates while cutting context costs.

01

Multi-Channel Candidate Recall

Subsystem: CandidateGenerator • 5 Orthogonal Discovery Channels

Coding agents frequently fail when initial search misses non-obvious callers or pulls in hundreds of irrelevant results. SiftrCode V2 runs Multi-Channel Candidate Recall across 5 orthogonal channels in parallel:

1. Exact Symbol / Path Matching

Identifies exact symbol names, functions, classes, and file paths referenced in the prompt or error report.

2. BM25 Lexical Retrieval

Probabilistic keyword ranking over exported docstrings, parameter names, and error string tokens.

3. Stack Trace Diagnostic Parser

Directly parses stack traces, runtime exceptions, and test failure outputs to pinpoint exact file and line offsets.

4. Context Graph & Git Co-Change

Traverses AST import/export caller graphs and mines git history for files that frequently co-modify together.

02

Point-in-Time Versioned Features

Subsystem: ContextFeaturesV1 • Strict Temporal FeatureCutoff Invariant

Context optimization must be scientifically reproducible and immune to evaluation leakage. SiftrCode models every candidate file as an immutable versioned feature vector (ContextFeaturesV1) with a strict featureCutoff timestamp.

No post-task commits, downstream edits, or runtime test outputs can leak into feature calculation. Features capture lexical affinity, graph centrality, error proximity, line count, and edit recency with deterministic provenance.

03

Deterministic ContextRank & Shadow JEV Architecture

Subsystem: ContextRank • TypeSafe Shadow JudgmentProvider • 100% Plan Invariance

Black-box neural rankers introduce non-deterministic ordering and unpredictability into production workflows. SiftrCode V2 maintains deterministic ContextRank as the sole production decision-maker, calculating an explicit finalScore alongside auditable reasons and component breakdowns:

ContextRank Scoring Formulation:
Score(c) = w_exact * s_exact + w_bm25 * s_bm25 + w_stack * s_stack + w_graph * s_graph - Penalties
Stack Trace Hits: +0.40 boost
Exact Identifier: +0.30 boost
Vendor / Build Dir: -0.50 penalty
Shadow JEV API Integration (Non-Interfering Calibration)

To validate semantic LLM judgments safely, Siftr forks candidate signals to a shadow JudgmentProvider in the background. Shadow JEV evaluates continuous relevance, edit target probability, and root cause localization (p95 latency 38.0ms) without altering any production ContextPlans (Plan_without_JEV == Plan_with_JEV). Only after verified benchmark evidence from SiftrBench can JEV influence ranking.

04

Submodular Synergy Composition

Subsystem: BundleComposer • Marginal Coverage Maximization & Synergy Boosts

Selecting context files independently leads to severe redundancy: multiple files defining identical helpers, or omitting the single type contract required to understand a causal function.

SiftrCode's BundleComposer applies submodular function optimization: each candidate added to the bundle is evaluated by its marginal utility gain relative to already-chosen files. Co-requisites (e.g. an interface file paired with its primary caller) receive a synergistic boost, while redundant utility mocks are quickly suppressed.

05

3-Stage Resolution Lineage & Discrete Method Slicing

Subsystem: ResolutionRank • Discrete Method BODY Isolation • Lineage Invariants

The fatal flaw in pure skeletonization is stripping the code the agent actually needs to rewrite. SiftrCode V2 eliminates this with 3-stage resolution lineage and discrete method body slicing:

3-Stage Resolution Lineage:
1. rankerResolution → 2. budgetedResolution → 3. finalResolution

Every ContextUnit tracks this immutable progression through solver budget allocation and post-render degradation. When an agent invokes siftr_expand to BODY, the Discrete AST Slicer isolates precisely the target function/method body while strictly excluding sibling methods, preventing context pollution.

06

Constrained Budget & Truthful Accounting

Subsystem: BudgetSolver & TokenizerRegistry • Knapsack Optimization

Context windows have hard operational ceilings. SiftrCode's BudgetSolver solves a constrained knapsack problem over candidate representations, maximizing cumulative utility per token without violating prompt budget limits.

Integrated with TokenizerRegistry, Siftr enforces pre-flight bounds calibrated against Claude BPE (~3.7 chars/tok) and GPT cl100k/o200k (~3.6 chars/tok), preventing context overflow and ensuring billing integrity.

Zero-Egress & Data Rights Technical Guarantees

Stage 0 Enforced

SiftrCode V2 is governed by immutable data rights, local-only processing, and structured egress security:

1. trainingAllowed: false

Zero machine learning training on your syntax, queries, or proprietary code.

2. rawSourceRetention: false

Zero raw source strings in SQLite. Automatically sanitized via ContextPlanMetadataRecord.

3. remoteProcessing: false

100% local CPU execution. 0 outbound network sockets opened during analysis.

4. UNEXPOSED_UNKNOWN

Unexposed candidate files are treated as unknown, never falsely assumed negative.

5. SIFTR_CALLS_ONLY

Conservative observability tracing capturing only Siftr tool invocations.

6. WorkspaceChangedError

Snapshot immutability guards trigger structured replanning if files mutate mid-task.

7. Egress Gateway & Redaction

Automatic regex redaction for AWS keys, Stripe secrets, and Bearer tokens prior to external dispatch.

8. Truthful AST Provenance
