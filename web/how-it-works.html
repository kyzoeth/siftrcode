THE V2 OUTCOME PIPELINE

The 6-Stage Optimization Engine

SiftrCode V2 replaces naive single-file pruning with a formal multi-stage context pipeline designed to maximize task completion.

01

Multi-Channel Candidate Recall

Channel Fusion: Exact, BM25, Stack Trace, Context Graph & Git Co-Change

Coding agents often fail before they even begin because naive search misses non-obvious dependency files or pulls in hundreds of irrelevant results. SiftrCode V2 implements Multi-Channel Recall across 5 orthogonal channels:

1. Exact Symbol / Path Match

Direct filename and identifier matching from user prompts and task specs.

2. BM25 Semantic Keyword Retrieval

Probabilistic relevance ranking over exported docstrings, types, and error tokens.

3. Stack Trace Diagnostic Parser

Extracts failing frames, filenames, and line offsets directly from runtime logs.

4. Context Graph & Git Co-Change

Traverses import/export caller graphs and historical git co-modification couplings.

02

Point-in-Time Versioned Features

ContextFeaturesV1 Schema & Strict FeatureCutoff Temporal Invariant

Context optimization must be scientifically reproducible and immune to evaluation leakage. SiftrCode models every candidate file as a versioned feature vector (ContextFeaturesV1) with a strict featureCutoff timestamp.

No future git commits, post-task edits, or test results can influence feature computation. Features capture retrieval scores, import depth, error proximity, and module centrality with deterministic attribution.

03

Transparent Heuristic Ranker

ContextRank • Explainable Reasons & Explicit Penalty Bounds

Black-box neural rankers introduce non-deterministic ordering and unpredictability. SiftrCode V2 uses a transparent linear combination ranker that calculates an explicit finalScore alongside human-auditable reasons and score breakdowns:

  • Boost Multipliers: Direct stack trace hits (+0.40), exact symbol matches (+0.30), direct caller adjacency (+0.25).
  • Domain Penalties: Vendor/generated directories (-0.50), standalone mock files (-0.25), distractor UI in backend tasks (-0.35).
  • Explainable Decisions: Every ranked candidate exposes an array of transparent audit strings explaining why it was promoted or deprioritized.
04

Submodular Synergy Composition

BundleComposer • Marginal Coverage Maximization & Diminishing Redundancy

Selecting context candidates individually leads to catastrophic redundancy: multiple files defining identical concepts, or missing the single contract required to understand a causal function.

SiftrCode's BundleComposer applies submodular function optimization: each candidate file added to the bundle is evaluated by its marginal information gain relative to already-chosen candidates. Co-requisites (e.g., an interface file and its primary implementation) receive a synergistic boost, while duplicates are swiftly suppressed.

05

Safe Variable-Resolution Degradation

Resolution Selection: Full Body vs AST Skeleton vs Signatures vs Drop

The fatal flaw in pure skeletonization is stripping the code the agent actually needs to rewrite. SiftrCode V2 eliminates this with outcome-aware variable resolution:

Full Body (100%)

Assigned to causal root and direct edit targets. 0 lines stripped.

AST Skeleton (-90%)

Preserves all exports, classes, interfaces, types, and parameter shapes.

Signatures (-95%)

Compact declaration lists for distant transitively-linked libraries.

Drop (-100%)

Completely filtered distractor files, saving 100% of non-causal tokens.

06

Constrained Budget & Cost Optimization

BudgetSolver • Sub-100ms Knapsack Optimization

Context windows have hard operational ceilings (e.g. 8,000 or 16,000 tokens for optimal reasoning speed and minimal cost). SiftrCode's BudgetSolver runs an exact knapsack algorithm over candidate representations, maximizing cumulative utility per token without violating hard prompt budget limits.

The result is an optimal context bundle containing everything necessary to complete the coding task, with zero token waste and zero latency penalty.

Zero-Egress & Data Rights Technical Guarantees

Sections 50–52 Enforced

SiftrCode V2 is governed by immutable data rights and algorithmic isolation enforced directly in code:

1. trainingAllowed: false

Zero machine learning training on your syntax, queries, or proprietary code.

2. rawSourceRetention: false

Volatile RAM processing only. Zero persistent raw source or token file logging.

3. remoteProcessing: false

100% local CPU execution. 0 outbound network sockets opened during analysis.

4. UNEXPOSED_UNKNOWN

Unexposed candidate files are treated as unknown, never falsely assumed negative.

5. RightsFilter Boundary

Strict firewall between raw telemetry and training datasets. Unvetted data is blocked.

6. Traceable Erasure

Cryptographic lineage links enable cascading right-to-be-forgotten purges with audit trail.
