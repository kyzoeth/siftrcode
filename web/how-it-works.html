How the Context Engine Works

A deterministic, submodular context optimization pipeline that transforms entire software repositories into high-signal agent prompt bundles.

End-to-End Execution Pipeline

STAGE 1
Indexing & Snapshots

Authoritative WorkspaceSnapshot captures git commit, tree hash, and parsed AST ContextUnits.

STAGE 2
Multi-Channel Recall

Fused retrieval combines exact symbols, BM25 lexical matches, call graphs, and git co-change.

STAGE 3
ContextRank & JEV

Ranks edit targets vs dependencies using point-in-time features and optional TypeSafe remote signals.

STAGE 4
BudgetSolver LP

Solves constrained token optimization, progressively degrading non-edit files to AST interface skeletons.

1. Multi-Channel Candidate Retrieval

Coding tasks require identifying files that need modification (edit targets) as well as the types, signatures, and interfaces they depend on (supporting context). SiftrCode does not rely on naive vector embeddings; it executes a multi-channel fusion:

Exact Symbol Matching:

Matches function, class, and method identifiers cited directly in prompt text, test failures, or stack traces.

Lexical BM25 Scoring:

Computes term-frequency inverse-document-frequency across tokenized identifiers, comments, and file paths.

Code Property Graph:

Traverses 1-hop and 2-hop neighbor relationships (imports, extends, implements, calls) from seed nodes.

Git Co-Change Intelligence:

Leverages repository historical commit logs to surface files that historically commit together with target units.

2. Variable-Resolution AST Degradation

3. Submodular Token & Economic Budgeting

Given a token ceiling (e.g., 16,000 tokens) and an optional economic budget ceiling ($0.05 / turn), SiftrCode’s BudgetSolver executes a linear optimization algorithm:

  • Priority Preservation: Files identified as edit targets or mentioned in active stack traces are locked at FULL resolution.
  • Progressive Degradation: If the total uncompressed tokens exceed the ceiling, non-priority candidates are degraded progressively (BODY → SKELETON → SIGNATURE → OMIT) ordered by lowest utility score.
  • Deterministic Invariance: Solves without stochastic heuristics, ensuring bit-for-bit identical decision plans across identical repository commits.
